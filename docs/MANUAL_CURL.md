# Manual cURL Guide（手动 cURL 兜底指南）

本指南面向普通用户：当自动抓取失败时，如何从浏览器开发者工具里找到招聘网站的请求，复制为 cURL，交给本程序完成采集。

- [用户指南](USER_GUIDE.md) | [中文 README](../README.zh-CN.md) | [English README](../README.md)

> **先说清楚**：绝大多数招聘网站用自动模式就能直接抓取成功（`python main.py "URL"`）。cURL 是**兜底方案**，只有在自动识别失败、程序主动提示时才需要用到。

## 1. 什么时候需要用 cURL

通常只有在自动识别招聘网站接口失败时才需要。典型情况：

- 页面上明明能看到岗位列表，但程序识别不到数据来源
- 网站的岗位数据接口需要在浏览器里才能正常返回
- 自动发现过程失败，终端显示 `自动识别失败`
- 网站使用了不常见的招聘系统或动态加载方式

程序失败时会主动询问 `是否使用 cURL 兜底？`——直接回车（默认 Y）即可进入本指南描述的流程。

> **安全边界**：本指南只针对你可以正常访问的公开招聘页面。请不要用 cURL 方式去绕过登录、验证码或访问限制。

## 2. 什么是 List cURL

**List 请求**是招聘网站用来加载「岗位列表」的请求。它的返回内容里通常能看到：

- 岗位名称
- 岗位 ID
- 工作地点
- 部门
- 分页信息（第几页、每页几条、共多少条）

复制下来的这个请求，就是 **List cURL**。程序拿到它之后，就能按同样的方式自动翻页，把所有岗位都抓下来。

## 3. 什么是 Detail cURL

**Detail 请求**是招聘网站用来加载「单个岗位详情页」的请求。它的返回内容通常包含：

- 岗位职责
- 任职要求
- 完整职位描述

复制下来的这个请求，就是 **Detail cURL**。你只需要复制**一个**岗位的 Detail 请求——程序会自动把每个岗位自己的 ID 填进去，逐个获取详情。

不是每个网站都需要 Detail cURL，见[第 9 节](#9-如果只有-list-curl)。

## 4. 打开 Chrome DevTools

一步一步来（以 Chrome 为例，Edge 操作基本相同）：

1. 用 Chrome 打开目标招聘网站的岗位列表页面
2. 打开开发者工具：
   - **Mac：** `Command + Option + I`
   - **Windows：** `F12` 或 `Ctrl + Shift + I`
3. 点击顶部标签栏里的 **Network**（网络）
4. 在 Network 面板的类型筛选里选择 **Fetch/XHR**
5. 按 `F5` 刷新页面

此时 Network 面板会出现一串请求记录，这就是网页背后实际发生的网络请求。

## 5. 怎么找到 List 请求

1. 在岗位列表页面上**正常翻页**（点"下一页"或第 2 页）
2. 观察 Network 面板里**新出现**的 Fetch/XHR 请求——翻页时新出现的那个，大概率就是
3. 逐个点击可疑请求，查看 **Preview**（预览）标签：
   - 如果能看到一串岗位标题、岗位 ID、地点等信息，就是它
4. 确认请求里带有分页痕迹（比如 URL 或参数里有 `page`、`pageIndex`、`pageSize`、`total` 之类）

不需要看懂整个 JSON，只要能在 Preview 里**看到岗位数据**即可。

## 6. Copy as cURL

在 Network 面板中，**右键**找到的那个请求：

```text
右键请求 → Copy → Copy as cURL (bash)
```

说明：

- 优先选择 **Copy as cURL (bash)**。旧版本 Chrome/Edge 菜单里只有一项 **Copy as cURL**，选它也可以
- **Windows 用户注意**：如果菜单里有 `(bash)` 和 `(cmd)` 两个选项，请选 **(bash)**。程序支持 bash 格式（`\` 换行、单引号）；`(cmd)` 格式使用 `^` 续行，程序无法解析
- 复制出来的是一段多行文本（很长是正常的），整体复制完整即可
- 程序只会**解析**这段文本提取请求信息，**不会把它当作命令执行**，可以放心粘贴

## 7. 怎么把 List cURL 提供给程序

自动模式失败后，程序会依次提示。照着终端提示操作即可：

```text
自动识别失败
是否使用 cURL 兜底？ [Y/n]        ← 直接回车（或输入 Y）
请粘贴 List cURL，完成后输入 END：  ← 粘贴完整的 cURL
curl 'https://jobs.example.com/api/postings?page=1' \
  -H 'Accept: application/json'
END                                ← 粘贴完成后，新起一行输入 END，再回车
```

关键规则：

- **直接粘贴完整的 cURL**（包括所有反斜杠换行），然后**新起一行**输入 `END` 并回车
- `END` 必须**单独占一行**。如果把 `END` 粘在了 cURL 末尾同一行，程序会提示"请输入单独一行 END 结束粘贴"
- 想中途放弃粘贴，新起一行输入 `CANCEL` 回车
- List cURL 解析失败时，程序会显示失败原因并让你**再试一次**（共两次机会）

粘贴成功后，程序会显示"已切换至 cURL 兜底"，然后自动开始翻页抓取。

> 备选方式：如果 cURL 特别长、不方便在终端粘贴，也可以把它保存成 UTF-8 文本文件，用命令行参数 `--list-curl-file <文件路径>` 和 `--detail-curl-file <文件路径>` 提供。注意：这种方式必须**同时**提供 List 和 Detail 两个文件。

## 8. 怎么找到 Detail cURL

1. 在网页上**点击任意一个岗位**进入详情页
2. 回到 Network 面板，看**新出现**的 Fetch/XHR 请求
3. 逐个点击，在 **Preview** 里找到包含完整 JD 的那个请求（能看到"岗位职责""任职要求"等文字内容）
4. 右键该请求 → Copy → Copy as cURL (bash)
5. 当程序提示时粘贴，方法与第 7 节完全相同（同样以单独一行 `END` 结束）

Detail cURL 只需要复制一次。程序会自动把列表里每个岗位的 ID 替换进这个请求，逐个获取详情——前提是这个请求里带有岗位 ID 参数（如 `postId`、`jobId` 等）。

## 9. 如果只有 List cURL

**可以只提供 List cURL。** 流程是这样的：

1. 你粘贴完 List cURL 后，程序会先自动抓完整个岗位列表
2. 然后程序会**自己尝试**获取 JD，按以下顺序：
   - 列表数据里本身就带 JD → 直接完成，无需 Detail cURL（终端会提示 `List 已包含完整 JD，跳过 Detail cURL。`）
   - 请求特征符合常见详情接口 → 自动获取
   - 用程序内置的无头浏览器打开每个岗位详情页 → 自动获取
3. 只有当以上自动方法都没拿到 JD 时，程序才会询问你：

```text
未能自动获取完整 JD（N 个岗位）。
1. 提供 Detail / JD cURL
2. 仅保存当前岗位 List
3. 取消
选择 [1]
```

- 输入 `1`（默认）：按第 8 节提供 Detail cURL
- 输入 `2`：**仅保存 List**。这是合法的完成方式——程序会把已抓到的岗位（标题、地点、部门等列表字段）正常保存成全部输出文件，只是 JD 内容为空，报告中会如实注明
- 输入 `3`：取消本次运行

也就是说：先给 List cURL，让程序先自己努力；实在不行再决定要不要补 Detail cURL。

## 10. 如果需要多条 cURL

程序**不需要也不支持**多条 List cURL：

- 只提供 **一份** List cURL，分页由程序自动完成（它会替换请求里的页码参数依次抓取）
- 最多再加 **一份** Detail cURL（同样只需一份，程序自动替换每个岗位的 ID）

输入顺序固定为：先 List、（仅在程序询问时）再 Detail，依次粘贴即可。你不需要为每一页或每一个岗位分别复制 cURL。

> 注意：如果 List 请求里没有页码参数（如 `page`），程序只会抓取第一页。所以尽量找**带页码参数**的那个请求。

## 11. 成功后会发生什么

提供 cURL 并回车后，程序自动继续：

1. 解析岗位列表，识别分页并逐页抓取
2. 去重、整理成唯一岗位记录
3. 获取详情 / JD（自动方法或你提供的 Detail cURL）
4. 保存到 `output/` 目录

最终得到与自动模式相同的 5 个文件（放在 `output/<公司名>/<时间戳>/` 下）：

| 文件 | 说明 |
|------|------|
| `jobs.json` | 完整结构化数据，交给 AI 首选 |
| `jobs.csv` | 表格浏览用 |
| `jobs.xlsx` | Excel 工作簿 |
| `report.md` | 运行报告，可读性最好 |
| `collection.json` | 采集过程元数据 |

各文件的详细用途见[用户指南第 9 节](USER_GUIDE.md#9-每个文件是干什么的)。

如果中途失败，结果会写入 `output/_failed/`，只包含 `error_report.json`。

## 12. 哪些 cURL 不要公开

**重点安全提醒。** 从浏览器复制出来的 cURL 可能包含：

- `Cookie`
- `Authorization`
- `Token`
- `Session`
- `Signature`

这些很可能是你的**登录凭证或会话信息**——别人拿到就能以你的身份访问该网站。

因此，**绝对不要把真实 cURL**：

- 上传到 GitHub
- 发到公开 Issue
- 放进 README 或任何文档
- 放进 examples 示例目录
- 提交到代码仓库
- 发到聊天群或截图里

如果需要提 Issue 反馈解析问题：先按下一节的清单检查，**删除或替换所有敏感请求头**后再贴出。

## 13. 怎么判断 cURL 里有没有敏感信息

粘贴或分享前，快速检查 cURL 文本里是否出现以下关键词（不区分大小写）：

```text
Cookie:
Authorization:
Bearer
token
session
signature
x-auth
csrf
```

只要出现其中任何一个，**默认当作敏感信息处理**：

- 提供给本程序使用没有问题（程序只在本地解析和请求，不会上传）
- 但**对外分享前必须删除**对应的 `-H '...'` 请求头（例如整行删掉 `-H 'Cookie: xxx'`），或把值替换成 `xxx`

## 14. 常见问题

**Network 面板里没有请求？**
确认左上角的红色录制圆点是亮的，然后按 `F5` 刷新页面。

**看不到 Fetch/XHR 类型筛选？**
点类型栏最右侧的 "All"，再用页面上的关键词（如 `list`、`post`、`job`）在请求名里搜索。

**翻页时没有新请求出现？**
说明列表可能是一次性加载的（不是接口分页）——这种情况自动模式通常本来就能识别；也可以尝试刷新页面后找首次加载时出现的数据请求。

**找不到 Detail 请求？**
详情页可能是整页跳转而不是接口加载。没关系，直接只提供 List cURL（见第 9 节），程序会用内置浏览器尝试打开详情页。

**cURL 太长，粘贴报 `UNSUPPORTED_CURL_OPTION`？**
你复制的可能是 `(cmd)` 格式——换用 **Copy as cURL (bash)** 重新复制粘贴。

**粘贴后一直没反应？**
程序在等你输入结束标记：**新起一行单独输入 `END` 再回车**。

**`END` 到底怎么用？**
粘贴完 cURL 后，新起一行只写 `END` 三个字母，回车。想放弃就单独一行输入 `CANCEL`。

**网站返回 401 / 403？**
通常是会话过期或网站有访问限制。重新打开页面、重新复制 cURL 并立即使用；若仍然失败，说明该站点需要登录态才能访问，请勿尝试绕过。

**提示"返回的数据不是有效 JSON"？**
你选中的请求不是岗位数据接口。回到 Network 里找 Preview 中能看到岗位列表结构的那个请求。

## 15. 示例

以下 cURL **完全虚构**，仅示意格式。真实的 cURL 会比这长得多（包含更多请求头），请完整复制粘贴：

List cURL 示例：

```bash
curl 'https://jobs.example.com/api/postings?page=1&pageSize=20' \
  -H 'Accept: application/json' \
  -H 'Accept-Language: zh-CN,zh;q=0.9' \
  -H 'User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)'
```

Detail cURL 示例：

```bash
curl 'https://jobs.example.com/api/postings/detail?postId=10086' \
  -H 'Accept: application/json' \
  -H 'User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)'
```

> 示例中故意没有 Cookie / Token。你复制的真实 cURL 里通常会有——**对外分享前务必按第 13 节脱敏**。
