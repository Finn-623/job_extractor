# Release Notes — v2.2.0-rc.1

> **Release Candidate / Pre-release。** 这是本仓库在 GitHub 上的首个 Pre-release。
> 默认离线回归已全部通过；**外部真实招聘网站的完整回归（live 测试）在本版本
> 发布时尚未重新执行通过**，随后续版本补验。

## 本次版本目标

补齐 JD 补全阶段的**时间控制、断点保护与恢复能力**，并把默认测试整理为
确定性的离线回归。

## 主要新功能

1. **JD 软时间预算**：`--jd-time-budget`（默认 300 秒）+ `--jd-on-timeout ask|skip`。
2. **Manual cURL Checkpoint**：JD 阶段部分完成或中断时，自动保存岗位列表与
   逐任务状态到 `output/_checkpoints/<run-id>/jd_checkpoint.json`。
3. **定向续抓**：`--resume-checkpoint` 只重试缺失/失败/被跳过的 JD，已成功任务保留。
4. **部分失败正式导出**：JD 部分失败仍输出全部五个正式文件（状态 `INCOMPLETE`）。
5. **五阶段动态进度**：首次 Detail API 探测状态、基于近期吞吐率的 ETA、
   连续 15 秒无完成事件提示、预算到期后已启动任务安全收束的状态显示。
6. **中断保护**：KeyboardInterrupt 时保留 task_states（checkpoint `JD_ABORTED`）。
7. **非 TTY 自动保存**：重定向/无人值守运行预算到期默认 `skip` 并保存部分结果。
8. **测试分层**：默认离线测试套件；真实站点测试 `pytest -m live` 显式 opt-in。

## 使用示例

```bash
# 常规 URL 抓取
python main.py "https://example.com/jobs"

# JD 阶段给 10 分钟预算，到期询问（TTY）
python main.py "URL" --jd-time-budget 600 --jd-on-timeout ask

# Manual cURL 兜底（cURL 只被解析，绝不被 shell 执行）
python main.py --list-curl-file list.txt --detail-curl-file detail.txt

# 从 Checkpoint 定向续抓缺失 JD
python main.py --resume-checkpoint "output/_checkpoints/<run-id>/jd_checkpoint.json" --detail-curl-file "detail.txt"
```

## Bug Fixes

- JD 补全失败不再导致整个运行无法正式导出。
- 中断时 checkpoint 的 task_states 不再丢失。
- UI 不再停留在过期进度。
- 初始 ETA 严重失真已修复。
- 部分结果场景下的并发指标统计已修正。

## 数据安全与恢复能力

- Checkpoint 只记录岗位数据与任务状态，不包含认证请求头；`output/_checkpoints/`
  又位于已被 .gitignore 忽略的 `output/` 之下，不应提交到 Git。
- cURL / HAR 的解析与导入均不执行 shell、不重放请求、不持久化 Cookie 或
  Authorization 值（与 v2.1.1 保持一致）。
- 恢复运行产生独立的新 Checkpoint（记录 `resumed_from`），已有可信 JD 始终保留。

## Known Limitations

- `300 秒`是 JD 阶段的**软预算**，不保证整个进程严格在预算时长内退出；已启动
  的请求会安全收束。
- Checkpoint 与定向续抓仅适用于 **Manual cURL 路径**；不能宣称所有平台 /
  采集器均支持。
- Generic / Provider 路径不全面支持本轮新增能力。
- 真实外部招聘网站的完整回归尚未重新验证。
- Hotjob 自动发现仍可能失败，需要 Manual cURL 兜底。

## 与 v2.1.1 的区别

v2.1.1 是纯文档收口版本。v2.2.0-rc.1 在其之上新增了 JD 阶段的软预算控制、
Manual cURL Checkpoint 与定向续抓、JD 部分失败的正式导出、五阶段动态进度
（ETA / 无事件提示 / 收束显示），并重组了测试分层（默认离线，live opt-in）。
