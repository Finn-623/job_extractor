# Job Extractor v2.1.0

This release adds a progressive fallback workflow for recruitment sites that cannot be collected reliably through normal HTTP requests: automatic collection first, then a manual cURL fallback, and — only when a site's pagination cannot be safely replayed — a browser-assisted collection mode with offline HAR import.

## Highlights

### Auto → cURL → Browser Assist

Collection is still automatic by default. When a site cannot be collected automatically:

1. **Auto first** — no manual input required.
2. **cURL fallback** — paste the job-list request copied from your browser's developer tools; it is parsed, never shell-executed.
3. **Browser-assisted collection** — only when the cURL reads jobs but the site signs its pagination requests with dynamic verification values (reported as a distinct "pagination not replayable" state). HAR import is never the default path.

### Browser-Assisted Collection

- Open the job list page in your normal browser with Network recording on
- Set the page size to its maximum in the site's own controls
- Run the bundled pagination helper in the console — it clicks the site's own next-page control and pauses automatically if the site shows a verification challenge
- Complete the site's verification yourself, manually, in your normal browser; the helper resumes automatically afterwards
- Export the Network recording as a HAR file once pagination finishes
- Import it: ingestion is fully offline, never re-plays requests, prefers the successful response when a page was first rejected and later succeeded, and deduplicates cross-page postings by stable ID

Validated on a dynamic-verification recruitment site: 16 pages recovered as raw 792 / unique 784 postings with the standard export pipeline.

### Unified Output

All three sources (automatic, cURL, HAR) produce the same structure through the same pipeline:

- `jobs.json` — machine-readable, best for AI workflows
- `jobs.csv` — flat table for spreadsheets
- `jobs.xlsx` — Excel workbook
- `report.md` — readable run summary
- `collection.json` — collection metadata and dedup audit

### Safety

- No captcha bypass — the site's own verification is always completed by you
- No anti-bot token generation
- No Cookie / Authorization persistence in outputs or logs
- HAR files and copied cURL commands may contain session material — treat them as sensitive local files and do not share them unreviewed

### Upgrade

No migration required from v2.0.0. Install/upgrade steps are unchanged — see the [README](../README.md#installation).

### Known Limitations

- The generic engine remains best-effort; not every site can be auto-collected
- The browser pagination helper currently supports verified pagination DOM patterns and is not a universal auto-pager
- Detail JDs may remain incomplete on strongly protected sites; completeness flags in `collection.json` and `report.md` always say exactly what was captured
- Some sites may ask you to complete their normal verification during browser-assisted collection
